⚠️ Узкие места и Ошибки
🔴 Массовое дублирование компонентов — Header (×3), Footer (×3), CardItem (×4), Breadcrumbs (×4), Pagination (×2), CatalogButton (×2), Modal (×2). Нужна консолидация с пропсами/вариантами через CVA
🔴 Лэндинги как компоненты — 8+ гигантских JSX-файлов по 20-30K байт (uerk, uerm, uerv, shity-etazhnye…). Монолитны, не переиспользуемы. Нужна CMS-based архитектура
🟡 Context + Zustand конфликт — CompareContext дублирует compareStore, ConsentContext пуст (4 bytes), а useConsentStore существует. Нужно выбрать одну систему
🟡 force-dynamic на весь проект — layout.jsx: export const dynamic = "force-dynamic" отключает ISR/SSG глобально. Для каталога электрооборудования это потеря перформанса
🟡 JSON-поля в Prisma — Order.items/customerInfo и Category.filters хранятся как JSON. Не типобезопасно, нельзя фильтровать на уровне БД
🟡 Мёртвый код — закомментированный блок в next.config.mjs (строки 55-79), testCartStore.js, ConsentContext.jsx
🟡 layout.jsx body class — dark:background и dark:textForeground не являются валидными Tailwind-классами (должно быть dark:bg-background, dark:text-foreground)
📋 Предложения по Улучшению
1. Консолидация компонентов — объединить Header/Footer/CardItem в единые компоненты с вариантами (CVA). Удалить дубли.
2. Единый State Manager — мигрировать CompareContext → Zustand. Удалить пустые файлы. Создать единый index.js для stores.
3. Гранулярное кэширование — вместо force-dynamic глобально, использовать per-route revalidation. Каталог → ISR 60s, корзина → dynamic.
4. CMS-слой для лэндингов — вынести контент uerk/uerm/uerv в JSON/MDX/БД, оставить один шаблонный компонент.
5. Заменить bcrypt на bcryptjs — в зависимостях оба (bcrypt и bcryptjs). bcrypt требует native build, bcryptjs — чистый JS. Для Docker лучше оставить только bcryptjs.
6. Типизация — добавить Zod-схемы для API endpoints (уже есть zod в зависимостях, но не видно повсеместного использования).

🔤 Типографика
Шрифты
  • Основной: Roboto (400, 500, 700) — для текста и UI
  • Моноширинный: JetBrains Mono — для артикулов, цен, технических данных
  • Fallback: system-ui, -apple-system, sans-serif
Шкала (Major Third)
  • Caption: 11px / 600 / uppercase / tracking 0.1em
  • Small: 13px / 400 / normal
  • Body: 15px / 400 / line-height 1.6
  • Lead: 18px / 400 / line-height 1.5
  • H4: 18px / 600 / tracking -0.02em
  • H3: 22px / 600 / tracking -0.02em
  • H2: 30px / 700 / tracking -0.03em
  • H1: 42px / 700 / tracking -0.04em
  • Display: 64px / 700 / tracking -0.04em
Правила
  • Цены и артикулы → JetBrains Mono, gold accent
  • Заголовки → Roboto Bold, tight tracking
  • Описания → Roboto Regular, comfortable leading

📐 Принципы Дизайна
Идентичность
  • Sovereign — каждый элемент выглядит выточенным, уверенным, контролируемым
  • Industrial — жёсткие формы, высокая плотность данных, минимальный «шум»
  • Premium — золотые акценты как знак качества, не украшение
Spacing (8px Grid)
  • 4px — micro (внутри тегов)
  • 8px — compact (между элементами)
  • 16px — base (padding карточек)
  • 24px — section (между блоками)
  • 48px — area (между разделами страницы)
Радиусы
  • 0px — теги, чипы (хардкор)
  • 4px — мелкие элементы (badge, tag)
  • 6px — кнопки, инпуты
  • 12px — карточки, модалки
Тени
  • Никаких box-shadow для карточек — только бордеры
  • Dropdown/Modal: 0 8px 30px rgba(0,0,0,0.5)
  • Glow-эффект для CTA: 0 0 20px rgba(212,168,83,0.2)
Анимации
  • Все transition: 150ms ease — быстро и чётко
  • Hover-карточки: border-color transition
  • Page-enter: fadeInUp 300ms
  • Никаких «жидких», «прыгающих» анимаций
